# 在 ling/798X (ImmortalWrt MT798x) 上编译

## 源码树情况
- 完整 ImmortalWrt 源码树，25.12 分支，内核 6.12
- 目标平台：`mediatek/filogic`（MT7981 / MT7986，Cortex-A53）
- 25.12 用 **apk** 包格式（不是老版本的 ipk）
- 我们的包是纯脚本/文件包，与芯片无关

## 一、放包

把 `openwrt-app` 分支 clone 到源码树 `package/diy/` 下（含后端和 LuCI 两个包）：

```sh
git clone -b openwrt-app <仓库地址>.git <798X源码>/package/diy/luci-app-xiaozhi-control
```

结构：
```
package/diy/luci-app-xiaozhi-control/
├── openwrt-xiaozhi-api/       # 后端
│   ├── Makefile
│   └── files/
│       ├── routerapi
│       ├── xiaozhi-api.config
│       ├── xiaozhi-api.init
│       └── oui-update.sh
└── luci-app-xiaozhi-control/  # 界面
    ├── Makefile
    └── files/
```

**注意**：Makefile 里声明了空的 `Build/Prepare` 和 `Build/Compile`（纯脚本包无源码要编）。如果用的是没有这两项的旧版本，编译会报 `No targets specified and no makefile found`。

## 二、配置

源码根目录有现成 defconfig，按路由器选：

```sh
cd <798X源码>
cp defconfig/mt7981-ax3000.config .config
make defconfig
make menuconfig
# Utilities  --->  xiaozhi-api
# LuCI  --->  3. Applications  --->  luci-app-xiaozhi-control
```

## 三、编译

**分开编**（一次编两个会拉起 kernel 等依赖链，慢）：

```sh
make package/diy/luci-app-xiaozhi-control/openwrt-xiaozhi-api/compile V=s
make package/diy/luci-app-xiaozhi-control/luci-app-xiaozhi-control/compile V=s
```

产物：
```
bin/packages/aarch64_cortex-a53/base/
├── xiaozhi-api-0.1-r1.apk
└── luci-app-xiaozhi-control-1.0-r1.apk
```

## 四、安装到路由器

```sh
scp bin/packages/aarch64_cortex-a53/base/*xiaozhi*.apk root@<路由器IP>:/tmp/
ssh root@<路由器IP>
apk add --allow-untrusted /tmp/xiaozhi-api-0.1-r1.apk /tmp/luci-app-xiaozhi-control-1.0-r1.apk
```

`apk add` 若卡在联网解析依赖，可直接热部署：把更新后的单文件覆盖到对应路径（routerapi → `/www/cgi-bin/routerapi`，JS → `/www/luci-static/resources/view/xiaozhi-control/xiaozhi-control.js`），再重启 rpcd / uhttpd。

## 五、验证

```sh
curl 'http://<路由器IP>/cgi-bin/routerapi?action=clients'
curl 'http://<路由器IP>/cgi-bin/routerapi?action=portforward_list'
curl 'http://<路由器IP>/cgi-bin/routerapi?action=route_list'
```

都返回合法 JSON 就成了。这一步不依赖小智，可单独验证。

浏览器打开 LuCI「服务 → 小智控制」，看两栏页面（配置 + 状态）是否正常。

## 常见问题

**Q：菜单里找不到 xiaozhi-control？**
A：确认 luci-app 包已编译安装，然后清浏览器缓存、重登 LuCI。

**Q：编译报 No targets specified and no makefile found？**
A：Makefile 缺空的 `Build/Prepare` / `Build/Compile` 定义，用最新版。

**Q：控制类工具调用报 disabled？**
A：要先开 `allow_control=1` 总开关，再单独开对应 permission（如 `route_add`），默认都是关的。

**Q：静态路由/端口映射功能不生效？**
A：端口映射必须有 `dest=lan`；静态路由写入后需 `network reload`。检查 UCI 配置是否生成。
