# OpenWrt 接入小智 —— 详细技术方案

## 一、目标

在 OpenWrt 路由器上提供 HTTP JSON 接口，在 ESP32 小智固件里加 MCP 工具调用它。对小智说话即可**查询**路由器状态（在线设备、WAN、系统、网络体检、端口映射、静态路由）并**控制**（端口映射、静态路由的增删，带二次确认）。同时提供 LuCI 管理界面。

固件自带连接云端大模型的能力，我们只做：OpenWrt 侧接口 + 固件侧工具 + LuCI 界面。

代码分两条独立分支维护（都是 orphan 分支，可单独 clone）：
- `openwrt-app`：OpenWrt 后端 + LuCI 界面
- `xiaozhi-firmware`：ESP32 固件侧工具

---

## 二、整体链路

```
你说"把 5000 端口映射到那台 NAS"
   ↓
小智 ESP32（固件自带连云端大模型）
   ↓ 语音上传
云端大模型 → 判断调 router.port_forward 工具
   ↓ MCP 下发
ESP32 执行 AddTool → HTTP GET 访问 OpenWrt routerapi
   ↓
OpenWrt → 返回确认码（此时未执行）
   ↓
大模型问你"确认吗？" → 你确认
   ↓
ESP32 调 router.port_forward_confirm（带确认码）→ 真正写 firewall
```

查询类（在线设备等）一步返回；控制类（端口映射、静态路由增删）必须两步确认。

**关键点**：ESP32 的网关 IP 就是路由器 IP（小智直连这台 OpenWrt 时成立），固件动态取网关，不用手填。

## 三、OpenWrt 侧

### 3.1 包格式

目标源码树 ImmortalWrt / OpenWrt 25.12（mediatek filogic 等），使用 **apk 包格式**（不是老版本的 ipk）：

```
bin/packages/aarch64_cortex-a53/base/
├── xiaozhi-api-0.1-r1.apk
└── luci-app-xiaozhi-control-1.0-r1.apk
```

两个包都是纯脚本/文件包，Makefile 里必须显式声明空的 `Build/Prepare` 和 `Build/Compile`，否则 OpenWrt 会去 build_dir 找 makefile 报错。

### 3.2 包目录结构

```
openwrt-app/
├── openwrt-xiaozhi-api/
│   ├── Makefile
│   └── files/
│       ├── routerapi          # CGI 脚本 → /www/cgi-bin/routerapi
│       ├── xiaozhi-api.config # UCI 配置 → /etc/config/xiaozhi-api
│       ├── xiaozhi-api.init   # 启动脚本
│       └── oui-update.sh      # OUI 厂商库下载（→ /tmp/oui.csv）
└── luci-app-xiaozhi-control/
    ├── Makefile
    └── files/
        ├── menu.d/luci-app-xiaozhi-control.json
        ├── acl.d/luci-app-xiaozhi-control.json
        └── view/xiaozhi-control.js
```

### 3.3 routerapi 接口清单

CGI 脚本跑在 uhttpd 下，接收 HTTP 请求返回 JSON。所有接口：

| 分类 | action | 参数 | 返回 | 数据来源 |
|---|---|---|---|---|
| 查询 | `clients` | — | `{"clients":[{"mac","ip","name"}]}` | ARP + DHCP + OUI 库 + name_map |
| 查询 | `wan` | — | `{"ip":..,"gateway":..}` | ifstatus wan |
| 查询 | `status` | — | `{"uptime":..,"model":..}` | /proc |
| 查询 | `health` | — | `{"score","grade","summary","checks","issues"}` | ifstatus + ping + nslookup + /proc + ARP |
| 查询 | `portforward_list` | — | `{"forwards":[{"name","ext","ip","in"}]}` | firewall DNAT redirect |
| 控制 | `portforward` | ext/ip/in/confirm | 确认码 / 执行结果 | 写 firewall（**必须 dest=lan**） |
| 查询 | `route_list` | — | `{"routes":[{"section","target","gateway","netmask"}]}` | network route |
| 控制 | `route_add` | cidr/gw/confirm | 确认码 / 执行结果 | 写 network route |
| 控制 | `route_del` | cidr/confirm | 确认码 / 执行结果 | 删 network route |

**health 体检项**：WAN 在线/IP、外网丢包与平均延迟、DNS 解析、网关延迟、系统负载（按 CPU 核数判断）、内存剩余、在线设备数与未命名设备数、conntrack 使用率。每项输出 `ok/warn/error`；`score` 从 100 扣分，`grade` 分优秀/良好/一般/较差，`issues` 是中文问题列表。全程只读，不写任何配置。

**内置 token 鉴权**：配置里 token 非 `change-me` 时，请求必须带 `?token=xxx`。

**JSON 注意**：uci show 输出值带单引号，解析要做处理；厂商名等字段要剔除 `\r\n\t` 控制字符，否则产出非法 JSON。

### 3.4 端口映射的关键点

生成 DNAT 规则**必须带 `option dest 'lan'`**：

```
config redirect
    option name 'xiaozhi_5000'
    option target 'DNAT'
    option src 'wan'
    option src_dport '5000'
    option dest 'lan'          ← 关键：缺失会变成"到此设备"本机规则
    option dest_ip '192.168.1.5'
    option dest_port '5000'
    option proto 'tcpudp'
```

### 3.5 静态路由的关键点

CIDR（`192.168.2.0/24`）要拆成 UCI 的 target + netmask 两段：

```
config route 'xiaozhi_route_192_168_2_0_24'
    option target '192.168.2.0'
    option netmask '255.255.255.0'
    option gateway '192.168.1.1'
```

写入后 `/etc/init.d/network reload`。用独立的 `xiaozhi_route_*` 段名，不动用户已有路由。

### 3.6 安全模型（控制类）

五层防护：

1. **token 鉴权** — 请求带 token
2. **控制总开关** — `xiaozhi-api.main.allow_control=1`
3. **每功能独立开关** — `config permission 'xxx'` 的 allow
4. **参数校验** — IP/CIDR/端口合法性
5. **二次确认码** — 第一步只返回 confirm 码，用户确认后带码才执行

查询类功能开关缺省允许，不受总开关影响；控制类缺省拒绝。

### 3.7 UCI 配置结构

```
config xiaozhi-api 'main'
    option token 'change-me'
    option allow_control '0'      # 控制类总闸

config permission 'portforward'       # 各功能独立开关
config permission 'portforward_list'
config permission 'route_add'
config permission 'route_del'
config permission 'route_list'
config permission 'clients'            # 查询类默认 1
config permission 'wan'
config permission 'status'
config permission 'health'             # 网络体检

config name_map                        # MAC → 友好名
    option mac 'aa:bb:cc:dd:ee:ff'
    option name '客厅电视'
```

### 3.8 OUI 厂商库

`/tmp/oui.csv`（重启会被清空），由 `/usr/bin/oui-update.sh` 下载。厂商识别优先级：name_map 映射 → DHCP hostname → OUI 厂商 → MAC。

## 四、固件侧：MCP 工具

### 4.1 文件

在独立分支 `xiaozhi-firmware`：

| 文件 | 说明 |
|---|---|
| `firmware_tool.cc` | 查询工具 + `GetGatewayIp()`：设备/系统 |
| `firmware_health.cc` | 网络体检：`router.network_health` |
| `firmware_control.cc` | 端口映射：port_forward / confirm / list |
| `firmware_route.cc` | 静态路由：route_list / add / add_confirm / del / del_confirm |

四个文件都放进固件 `main/`，`GetGatewayIp()` 定义在 `firmware_tool.cc`，其他文件依赖它。

### 4.2 动态获取网关 IP

```cpp
static std::string GetGatewayIp() {
    esp_netif_t* netif = esp_netif_get_handle_from_ifkey("WIFI_STA_DEF");
    if (netif == nullptr) return "";
    esp_netif_ip_info_t ip_info;
    if (esp_netif_get_ip_info(netif, &ip_info) != ESP_OK) return "";
    char buf[16];
    return std::string(esp_ip4addr_ntoa(&ip_info.gw, buf, sizeof(buf)));
}
```

### 4.3 工具清单

工具名用 `router.xxx` 格式（源码 `docs/mcp-usage_zh.md` 建议"模块.功能"）。回调返回类型必须是 `ToolResult`。

| 工具 | action | 说明 |
|---|---|---|
| `router.get_clients` | clients | 在线设备 |
| `router.get_wan_status` | wan | WAN 状态 |
| `router.get_system_info` | status | 系统状态 |
| `router.network_health` | health | 网络体检报告（评分 + 各项检查 + 问题列表） |
| `router.port_forward` | portforward | 映射预览，取确认码 |
| `router.port_forward_confirm` | portforward | 带码执行 |
| `router.port_forward_list` | portforward_list | 查看映射 |
| `router.route_list` | route_list | 查看静态路由 |
| `router.route_add` | route_add | 路由预览，取确认码 |
| `router.route_add_confirm` | route_add | 带码执行 |
| `router.route_del` | route_del | 删除预览，取确认码 |
| `router.route_del_confirm` | route_del | 带码执行 |

工具描述要写清楚"什么时候用"，大模型靠这个判断。控制类必须提示"先取确认码，用户确认后再调 confirm"。

### 4.4 编译

按 `xiaozhi-esp32` 官方流程（ESP-IDF 6.0.1+，推荐 release/v6.1）：

```sh
. $IDF_PATH/export.sh
idf.py build flash monitor
```

## 五、LuCI 界面

`luci-app-xiaozhi-control`，挂在「服务 → 小智控制」菜单。

**布局**：桌面端两栏（配置 / 状态），窄屏（<900px）自动堆叠。

- **左栏配置**：token、控制总开关、各功能开关（数据驱动的 FEATURES 数组，加功能只加一项）
- **右栏状态**：网络体检评分卡（分数/等级/各项检查/问题）、在线设备表、端口映射表、静态路由表（实时读取，无需保存）

**注意**：后端 config 加了 permission 后，前端 FEATURES 数组必须同步加，否则界面不显示开关。

LuCI 25.12 的几个坑：
- `form.Map.render()` 返回 Promise，必须 `.then(node => ...)`
- anonymous TypedSection 无 UCI 段时 option 不渲染，状态区改用 DOM 填充
- `fs.read('/proc/...')` 在 rpcd 下无权限，改用 `fetch` 自身 CGI
- 两栏 CSS 依赖 LuCI 原生 class（`.cbi-section` 等）

## 六、编译与安装

### 6.1 编译（单独编译包，避免拉起全量依赖）

```sh
cd <798X源码>
# 应用仓库 clone 到 package/diy/luci-app-xiaozhi-control/（openwrt-app 分支）
make package/diy/luci-app-xiaozhi-control/openwrt-xiaozhi-api/compile V=s
make package/diy/luci-app-xiaozhi-control/luci-app-xiaozhi-control/compile V=s
```

一次 make 两个包会触发 kernel 等依赖链，慢。分开编。

### 6.2 安装

```sh
scp xiaozhi-api-0.1-r1.apk luci-app-xiaozhi-control-1.0-r1.apk root@<路由器IP>:/tmp/
ssh root@<路由器IP>
apk add --allow-untrusted /tmp/xiaozhi-api-0.1-r1.apk /tmp/luci-app-xiaozhi-control-1.0-r1.apk
```

在线安装若卡在网络解析依赖，可直接热部署：把更新后的单文件（routerapi / JS）覆盖到对应路径。

### 6.3 验证接口

```sh
curl 'http://<路由器IP>/cgi-bin/routerapi?action=clients'
curl 'http://<路由器IP>/cgi-bin/routerapi?action=health'
curl 'http://<路由器IP>/cgi-bin/routerapi?action=portforward_list'
curl 'http://<路由器IP>/cgi-bin/routerapi?action=route_list'
```

能返回合法 JSON 就说明 OpenWrt 侧正常，这一步不依赖小智。

## 七、测试顺序

分三层，出问题好定位：

1. **接口层**：curl 访问 CGI，看 JSON 对不对、是否合法 ← 先做这个
2. **页面层**：浏览器开 LuCI 页面，看开关和状态表格
3. **整机层**：对小智说话，听播报

不要一上来就测整机。控制类功能测完记得把开关恢复默认关闭。

## 八、安全

- **默认全关**：控制类（端口映射、静态路由增删）默认关闭，且受总开关约束
- **二次确认**：所有写操作都先返回确认码，用户确认后才执行
- **token 鉴权**：防止局域网里任何人调用
- **参数校验**：IP / CIDR / 端口严格校验，避免注入
- **独立段名**：小智创建的规则用 `xiaozhi_` 前缀，不碰用户已有配置
