# OpenWrt 接入小智 —— 详细技术方案

## 一、目标

在 OpenWrt 路由器上做一个**标准 ipk 应用**，提供 HTTP JSON 接口；在 ESP32 小智固件里加 `AddTool` 工具调用这个接口。这样对小智说话，就能查询路由器的信息（在线设备、WAN 状态、系统状态）。

固件本身自带连接云端大模型的能力，这部分不用我们做。我们只做两件事：

1. OpenWrt 侧：标准 ipk 包，提供查询接口
2. 固件侧：加一个工具，调用接口

---

## 二、整体链路

```
你说"家里谁在线"
   ↓
小智 ESP32（固件自带连云端大模型）
   ↓ 语音上传
云端大模型 → 判断该调 router.get_clients 工具
   ↓ MCP 下发
ESP32 执行 AddTool 回调 → HTTP GET 访问 OpenWrt 接口
   ↓
OpenWrt ipk 应用 → 读 DHCP 租约 → 返回 JSON
   ↓
ESP32 把 JSON 回给大模型 → 大模型组织语言 → 小智播报
```

**关键点**：ESP32 和你的电脑/手机在同一个局域网，能直接访问路由器 IP，不需要公网。

## 三、OpenWrt 侧：标准 ipk 包

### 3.1 为什么用标准包

直接传脚本能用，但不规范：升级要手动覆盖、不知道装没装、卸载留垃圾、配置没地方放。做成 ipk 包后：

- `opkg install` 一条命令安装
- 配置文件独立，升级不丢
- `opkg remove` 干净卸载
- 可以进 LuCI 软件列表，可分发

### 3.2 包目录结构

```
openwrt-xiaozhi-api/
├── Makefile                    # OpenWrt 构建规则（定义包名、依赖、安装路径）
└── files/
    ├── routerapi               # CGI 脚本，安装到 /www/cgi-bin/routerapi
    └── xiaozhi-api.config      # UCI 配置，安装到 /etc/config/xiaozhi-api
```

### 3.3 各文件作用

**Makefile**：标准 OpenWrt package 模板（`include $(TOPDIR)/rules.mk` + `BuildPackage`）。声明：
- 包名 `xiaozhi-api`、版本 0.1
- 依赖 `jsonfilter`（解析 ifstatus 的 JSON，OpenWrt 自带）
- 安装时把 CGI 脚本放到 `/www/cgi-bin/`，配置放到 `/etc/config/`
- `conffiles` 标记配置为配置文件，升级时保留

**routerapi**：CGI 脚本，跑在 uhttpd 下，接收 HTTP 请求返回 JSON。三个接口：

| 接口 | URL | 返回 | 数据来源 |
|---|---|---|---|
| 在线设备 | `?action=clients` | `{"clients":[{"mac":..,"ip":..,"name":..}]}` | `/tmp/dhcp.leases` |
| WAN 状态 | `?action=wan` | `{"ip":..,"gateway":..}` | `ifstatus wan` |
| 系统状态 | `?action=status` | `{"uptime":..,"model":..}` | `/proc` |

内置简单 token 鉴权：配置里 token 非默认值时，请求必须带 `?token=xxx`。

**xiaozhi-api.config**：UCI 配置，存 token 和端口。

### 3.4 CGI 方式说明

OpenWrt 的 Web 服务器是 uhttpd，它把 `/www/cgi-bin/` 下的可执行脚本当 CGI 跑。所以我们的"接口"就是一个 shell 脚本：
- 请求进来，uhttpd 调用脚本
- 脚本读 `QUERY_STRING` 拿参数
- 先输出 `Content-Type` 头，再输出 JSON
- 无需常驻进程，零额外内存开销

## 四、固件侧：AddTool 工具

### 4.1 加在哪

你发的仓库 `main/mcp_server.cc` 里有个 `InitializeTools()`（或类似函数），里面已经注册了 `self.get_device_status`、`self.audio_speaker.set_volume` 等工具。照着它们的格式加我们的工具即可。

### 4.2 工具代码

```cpp
AddTool(
    "router.get_clients",
    "Get devices connected to the OpenWrt router, with IP and hostname",
    PropertyList(),
    [](const PropertyList& properties) -> ReturnValue {
        auto http = Board::GetInstance().GetNetwork()->CreateHttp(3);
        if (auto opened = http->Open("GET", "http://192.168.1.1/cgi-bin/routerapi?action=clients"); !opened) {
            return std::unexpected("Failed to open: " + opened.error().ToString());
        }
        auto status = http->GetStatusCode();
        if (!status || *status != 200) return std::unexpected("HTTP error");
        std::string body = http->ReadAll();
        http->Close();
        return body;
    });
```

这段完全照抄仓库里 `self.screen.preview_image` 的写法（HTTP GET），只是换了 URL。

### 4.3 工具命名规范

源码 `docs/mcp-usage_zh.md` 建议用"模块.功能"格式，我们用 `router.xxx`：
- `router.get_clients` — 在线设备
- `router.get_wan_status` — WAN 状态
- `router.get_system_info` — 系统状态

工具描述要写清楚"什么时候用"，大模型靠这个判断。

### 4.4 返回值限制

源码规定单工具返回文本建议 < 1024 字节。在线设备多时可能超，建议：
- 只返回必要字段（IP + 名字）
- 或在 CGI 侧限制数量

## 五、编译与安装

### 5.1 编译 ipk（在 OpenWrt SDK 里）

```sh
# 1. 把包目录放进 SDK
cp -r openwrt-xiaozhi-api/ <sdk>/package/

# 2. 选目标平台（x86/ARM/MIPS 按你的路由器）
cd <sdk>
make menuconfig       # 确认 Utilities → xiaozhi-api 已勾选
make package/xiaozhi-api/compile V=s

# 3. 产物
bin/packages/<arch>/base/xiaozhi-api_0.1-1_<arch>.ipk
```

### 5.2 安装到路由器

```sh
scp xiaozhi-api_0.1-1_*.ipk root@192.168.1.1:/tmp/
ssh root@192.168.1.1
opkg install /tmp/xiaozhi-api_0.1-1_*.ipk
```

### 5.3 验证接口（先用浏览器/curl 测）

```sh
curl 'http://192.168.1.1/cgi-bin/routerapi?action=clients'
```

能返回 JSON 就说明 OpenWrt 侧成了。这一步**不依赖小智**，可以单独验证。

### 5.4 编译固件

取独立分支 `xiaozhi-firmware` 里的 `firmware_tool.cc`，将其中 `AddTool` 代码加到 `main/mcp_server.cc`，按仓库 README 用 ESP-IDF 6.x 编译烧录。

## 六、测试顺序（重要）

分三层测，出问题好定位：

1. **接口层**：浏览器/curl 访问 CGI，看 JSON 对不对 ← 先做这个
2. **工具层**：用普通 MCP Client 调工具（可选）
3. **整机层**：对小智说话，听播报

不要一上来就测整机，问题难查。

---

## 七、安全

- **token 鉴权**：配置里设非默认 token，请求要带 `?token=`，防止局域网里任何人查
- **只读优先**：第一版只做查询，不碰控制（重启、改配置），零风险
- **后续加控制**：必须加白名单 + 二次确认（"确定重启吗？说确认"）

---

## 八、后续扩展（第二版再做）

- 加控制类工具：开关访客网络、重启服务（带确认）
- 数据缓存：设备多时避免每次读文件
- 更多接口：流量统计、QoS、USB 设备

---

## 九、需要你确认的两件事

1. **OpenWrt 的实际 IP**：代码里写的是 `192.168.1.1`，按你实际改
2. **先做哪几个接口**：建议第一版只做 `clients`（在线设备），跑通再加其他
